# مِيزان — مشروع هندسي لتحليل المشاعر العربية

التطوير يحافظ على نموذجك BiLSTM + Self-Attention ويضيف API وواجهة عربية، تحليل دفعات/CSV، سجل SQL وتصحيحات بشرية، Docker، اختبارات ومسار تدريب ومقارنة MLflow.

## شغّله على Windows

فك الحزمة في مجلد جديد `mizan-sentiment` ثم:

```bat
cd "C:\Users\gemar\OneDrive\سطح المكتب\mizan-sentiment"
python scripts/check_artifacts.py
docker compose up --build -d
start http://localhost:8092
```

المنفذ 8092 لا يتعارض مع مشروع الأخبار 8091. النموذج داخل الحزمة؛ لا تحتاج تنزيل بيانات تدريب أو تسجيل حساب. التشغيل CPU، وليس تسريع GPU. الـAPI عند `/docs`. افتراضيًا لا تحتاج مفتاحًا محليًا؛ يمكنك إضافته في `.env` عبر `APP_API_KEY` ثم إعادة إنشاء api.

الواجهة تدعم نصًا واحدًا أو دفعة (كل نص بسطر) وCSV، مع اسم عمود قابل للتحديد، تنزيل نتائج CSV وتصحيح التصنيف. الحد 100 نص للطلب؛ CSV بحجم تقريبي 1MB، وأسماء الأعمدة تُقرأ من CSV فعليًا. النصوص غير الصالحة توقف الطلب برسالة، ولا يُختلق تصنيف بديل.

## نتائج الجودة بصدق

الدقة القديمة 83.62% وmacro F1 القديم 0.83 ليسا إثباتًا مستقلًا: الـnotebook الأصلي يكرر neutral قبل التقسيم، ويدرّب tokenizer على كامل البيانات. قد يوجد تداخل للنصوص بين التدريب والاختبار. لا يمكن إصلاح تقييم النموذج الموجود بتعديل الكود فقط؛ يلزم إعادة تدريب وتقسيم نظيف من البيانات الأصلية غير المرفقة.

تم توفير مسار تدريب جديد: تنظيف موحّد → إزالة تكرار النص المنظف ورفض تضارب التصنيفات → تقسيم طبقي 70/15/15 → تعلم المفردات من train فقط → class weights من train → مقارنة Logistic Regression + TF-IDF مع BiLSTM → اختيار وفق validation macro F1 → تقرير test دون استخدامه للاختيار.

ضع بياناتك محليًا في `data/dataset.csv` بالأعمدة `review_description,rating` (القيم -1،0،1). ثم اتبع أوامر التدريب في README.md أو افتح `notebooks/Training.ipynb`. يوجد CSV اصطناعي صغير لتجربة المسار فقط؛ درجاته لا تعبّر عن جودة حقيقية.

## أين قاعدة البيانات والتتبع؟

- SQL سجل التنبؤات والتصحيحات: SQLite في `/app/state/audit.sqlite` داخل volume باسم `mizan-sentiment_audit-data`.
- لا تُحفظ النصوص الخام؛ تحفظ request IDs والتصنيفات والمدة والإصدار وعلامة المراجعة.
- `/monitoring` يعرض إحصاءات التشغيل فقط؛ ليس drift إحصائيًا أو قياس دقة.
- MLflow في التدريب: قاعدة `state/mlflow.db` وتقارير `reports/`، ويمكن عرضها على منفذ 5002. لا يوجد LangSmith/LLM في هذا المصنّف.
- التصحيحات لا تعيد التدريب تلقائيًا، وعدم تخزين النصوص يعني أن عليك الاحتفاظ ببيانات التدريب والمراجعة المرخصة خارجيًا.

## ما تغير في النموذج؟

لم نغيّر الأوزان أو نزعم تدريبًا محسّنًا على بيانات حقيقية. أُعيد حفظ النموذج دون حالة optimizer لتقليل الحجم، واختُبر تطابق المخرجات على ثلاثة أمثلة. tokenizer والتصنيفات في JSON بدل pickle؛ stopwords مرفقة ولا يُحمّل NLTK عند بدء التطبيق. التضمين الحقيقي 128 بُعدًا كما في ملف النموذج، وليس 64 المذكورة في README القديم.

الدرجة softmax وليست «شعور قوي جدًا» أو ضمان صحة؛ عُرض التصنيف الحقيقي منفصلًا عن درجة النموذج ومؤشرات OOV والاقتطاع والمراجعة. لا توجد تفسيرات سببية مختلقة من قوائم كلمات. النموذج القديم يحتفظ بسلوكه تجاه padding حفاظًا على التطابق.

المشروع يثبت TensorFlow والتقييم والخدمات الهندسية. لا نضيف ادعاء RAG/LLM لمجرد مطابقة الإعلان؛ يغطيهما مشروعك الآخر. انظر `docs/JOB_MATCH_AR.md`.

## حدود النشر

لم يُختبر Docker أو cloud هنا. API محلي، عامل واحد وقفل للتنبؤ، بلا صلاحيات متعددة أو rate limiting. لا تستخدمه لاتخاذ قرارات مؤثرة على الأشخاص دون مراجعة. لم يرفق مصدر وترخيص مجموعة البيانات؛ تأكد من حق نشر النموذج ومفرداته قبل رفع artifacts علنًا.
